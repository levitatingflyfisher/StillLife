# How to export your inventory (for insurance, spreadsheets, or backup)

Goal: get your catalogue out of the app — as a shareable insurance **PDF**, a
spreadsheet **CSV**, or a full **JSON backup** you can restore.

Still Life gives you three export formats, each for a different job. All three run
**entirely on-device**; none require a network or an account.

## PDF report — for an insurer or a claim

A formatted report grouped by room and category, with per-item value, replacement cost,
and acquisition totals — the document you'd hand to an insurer or attach to a claim.

- **Where:** Reports / Export → generate PDF report (optionally scoped to one property).
- **What's in it:** items with their values, organised by location, plus household
  totals. Generated by `pdf_report_generator.dart` using the `pdf`/`printing` packages.
- **Then:** share or print it via the system share sheet.

## CSV — for a spreadsheet or an insurer's template

A spreadsheet-ready file (RFC 4180 quoting) with one row per item and columns for name,
category, room, container, condition, purchase / current / replacement value, dates,
serial, barcode, label ID, notes, insured flag, and tags.

- **Where:** Settings → Data Management → Export as CSV.
- **Safe to open anywhere:** cells that begin with `=`, `+`, `-`, or `@` are escaped so
  a spreadsheet can't execute them as formulas — your data can't become a payload.
- **Also available:** a "shopping list" CSV of items below their low-stock threshold.

## JSON backup — for moving or restoring

A complete structured dump of every table (items, rooms, containers, categories, tags,
photos*, receipts, price history, policies, maintenance, loans, profiles, appraisals),
suitable for a full restore.

- **Where:** Settings → Data Management (export to a file), or **WebDAV backup** to send
  it to your own server (HTTPS-enforced).
- **Restore:** import the JSON back in. A restore is a **wholesale replace** of local
  data (distinct from a sync *merge*, which is last-writer-wins). Imports are sandboxed
  and transactional, so a bad file can't corrupt your database
  ([ADR-0006](../adr/0006-import-db-safety.md)).

> **\*Photos are metadata-only.** The JSON export records that an item *has* a photo and
> where its file lives, but does **not** embed the image bytes (`photosIncluded: false`).
> A restore on a device that lacks those files rebuilds the catalogue without the
> images. Keep the image files alongside the backup if you need them to travel. See
> [limitations](../limitations.md).
